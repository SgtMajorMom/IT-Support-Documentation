# Onboarding Guide: New Hire SaaS Access Assignment

## Purpose
Ensure new hires receive the correct SaaS application access, licenses, and permissions based on their role, department, and manager requirements.

## Trigger
Use this guide when:
- A new hire is starting
- A contractor or intern is joining
- A role change requires new SaaS access

---

## 1. Validate Role Requirements
- Confirm department (IT, HR, Finance, Sales, etc.)
- Confirm job title and responsibilities
- Review manager’s access request
- Identify role‑based access templates (if available)

---

## 2. Assign Core SaaS Applications

### Communication & Collaboration
- [ ] Slack or Microsoft Teams  
- [ ] Zoom (license type: Basic, Pro, or Admin)  
- [ ] Email (Google Workspace or M365)  
- [ ] Shared drives or folders  

### Productivity
- [ ] Google Drive / OneDrive  
- [ ] Microsoft 365 Apps  
- [ ] Calendar access (team calendars, resource calendars)  

---

## 3. Assign Department‑Specific SaaS Tools

### IT / Security
- [ ] Ticketing system (Jira, Freshservice, Zendesk)  
- [ ] Monitoring tools (if applicable)  
- [ ] Security tools (Proofpoint, Defender, etc.)  

### Sales / Marketing
- [ ] CRM (Zoho, Salesforce, HubSpot)  
- [ ] Marketing automation tools  
- [ ] Analytics dashboards  

### HR / Finance
- [ ] HRIS platform  
- [ ] Payroll/benefits systems  
- [ ] Finance or accounting tools  

### Operations / Support
- [ ] Knowledge base access  
- [ ] Phone/VoIP system  
- [ ] Inventory or asset management tools  

---

## 4. Assign Access via Groups (Preferred Method)
Whenever possible, assign access using:
- Identity provider groups (Okta / Entra ID / Google)
- SaaS role groups
- Department groups
- Application‑specific RBAC groups

This ensures:
- Consistency  
- Least privilege  
- Easier offboarding  
- Better auditability  

---

## 5. Validate License Assignment
For each SaaS platform:
- Confirm license type is correct  
- Confirm user appears in the admin console  
- Confirm provisioning completed successfully  
- Confirm no conflicting roles or duplicate licenses  

---

## 6. Validate Access Functionality
Have the user confirm:
- They can sign in  
- MFA works (Duo / PingID)  
- Apps load correctly  
- Required permissions are present  
- Shared resources are visible  

---

## 7. Notify Manager
Send confirmation that:
- SaaS access is fully provisioned  
- Any pending approvals are noted  
- User is ready for Day 1 work  

---

## Expected Outcome
New hire has all required SaaS access, licenses, and permissions to perform their role effectively from Day 1.

## Escalation
Escalate to:
- Security for MFA or identity issues  
- SaaS application owners for role conflicts  
- Systems team for provisioning failures
